# Next bounded SCORE design after337 (not yet an experiment/source change)

Decision: there is sufficient fresh certificate evidence to investigate a bounded
joint pair W1 consumer. There is not yet evidence to replace the production bot.
No designed functionality is removed, disabled, deferred or reduced. Nothing is
deleted. Existing full W1 construction, exact bundle witness, candidate pool,
current-day floor, scenario certification, ACK cache and deadline policy remain.

## Why this is a different mechanism

332 priced one Patrol at a time and failed actual-score breadth despite complete
work.333 found no certificate loss through ACK.334 showed independent best
responses cannot simply be combined safely.335 demonstrated an individually
losing but jointly beneficial pair;336 constructed it without oracle input.337
replicated selected-witness pair benefit on fresh setups. Thus the proposed
change is joint stock-capped value across two physical resource trajectories,
not a longer clock, repeated rejected single pricing, tied-route retention or
forced ACK consumption. Consumed evidence cannot promote a successor.

## Runtime placement and preserved responsibilities

Trace FutureWitnessRepairer::certify in decision.cpp, existing completed witness
and exact-bundle comparison, then profile outcome/finalization/selection; follow

revalidation.336 is an independent research DP using the historical day frontier;
production integration must reuse the canonical sparse resource enumerator and

For a complete original witness and exact post-current-action state/ledger,
consider each unordered Patrol pair independently with every other physical
trajectory fixed. Joint day value is stock-capped claims plus union brands;
carried cell/fuel/lifetime brands are sufficient only in the proven roadless
all-Patrol domain. No local single-Patrol non-regression pruning. No sequential
coordinate updates or injected oracle plans. Other roles/traffic remain on the
unchanged existing full planner until a separate valid state model exists.

## Unresolved design gate before implementation

The research DP has no useful production deadline guarantee: pair work is far
larger than single work. Establish a shared bounded label/memo/transition/action
accounting contract including generation, allocations, cross products,
reconstruction and both validators. A limit hit is incomplete, not optimal.
Keep the original complete witness byte-identical on failed/incomplete attempts;
only a complete exact-valid strictly improved replacement may be published.
All resource ceilings and the invocation deadline must be fixed before new
measurement, within the existing certification budget and5000ms main cap.
Do not infer that a new cap is justified because337 recorded292336transitions.
Decide pair ordering and completion semantics from invariant/contract tests,
not by choosing the order that wins on these observed families.

Fresh small exhaustive tests must check paired-route frontier equivalence,
per-agent physical identity, stock1..agents, all relevant initial-spot WAIT
semantics, carried fuel, whole-horizon ledger, malformed witness, deadline and
each resource ceiling, and byte-identical original on failure. Native/fixed
roles and road paths must preserve existing behavior outside the proven domain.

## Evidence chain before any product change

Register a new SCORE id/parent and freeze new development, sealed holdout and
protected input hashes before candidate source changes. Freeze candidate binary,
runner, comparator, strata and acceptance gate before measurements. Paired actual
closed-loop HTTP candidate versus canonical parent must be measured; alternated
order and inactive-path controls are required to separate cutoff noise. Report
official W/T/L, first tiers, magnitude and tail loss by all public strata. Do
not count certificate-only gains or BTC rank as actual strength evidence.
